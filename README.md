# 後付け小黒板

撮影済みの写真に、工事用の小黒板をあとから合成して JPEG で書き出すブラウザアプリです。
`index.html` 1ファイルだけで動きます。写真はブラウザの中だけで処理されます。「サーバーに保存」を押したときだけ、Vercel Blob に送信されます。

## 使い方

1. `index.html` をブラウザで開く（GitHub Pages などで公開してもそのまま動きます）
2. 「写真を追加」から写真を選ぶ（ドラッグ＆ドロップも可、複数枚OK）
3. 黒板の内容を入力し、黒板をドラッグして位置と大きさを決める
4. 「この写真を保存（JPEG）」で書き出す。写真が2枚以上あるときは「全○枚保存」で全部まとめて保存できます（パソコン: ZIPにまとめてダウンロード / スマホ: 共有シートで写真アプリへまとめて保存 / アプリ版: 写真アプリへ順番に直接保存）

## 機能

- 黒板の項目: 工事名 / 工種 / 測点・箇所 / 場所 / 部屋番号 / 備考 / 撮影日 / 施工者
- 項目ごとに「共通」（全写真で同じ内容）か「写真ごと」を選べます。標準では工事名と施工者が共通、ほかは写真ごとです。入力欄も、この選択に合わせて「全写真で共通の内容」と「この写真だけの内容」に分かれます
- 黒板の項目は、チェックで表示・非表示を切り替え、▲▼で順番を入れ替えられます（全写真で共通）。表示する項目に合わせて黒板の高さが変わります。標準で表示するのは工事名・工種・備考・撮影日・施工者です（測点・箇所、場所、部屋番号は必要なときにチェック）
- 写真の加工（写真の上の「✎ 加工・書き込み」）: 回転（左右90度）、トリミング（自由／1:1／4:3／3:4／16:9）、明るさ・コントラスト・鮮やかさの調整。元の写真は残り、何度でもやり直せます。加工した写真には「加工済み」と表示されます。公共工事の提出写真では撮影後の加工を認めない基準があります
- 文字・図形の書き込み（同じ画面の「文字・図形」タブ）: 文字（背景なし／白／黒）、四角、丸、矢印を置けます。色・太さ・大きさの変更、移動、削除、「1つ戻す」に対応。書き込みは写真ごとに持ち、書き出し・まとめて保存・サーバー保存の画像に入ります（黒板は書き込みの上に重なります）。回転・トリミングを変えると、その写真の書き込みは消えます（加工→書き込みの順で使ってください）
- 撮影日は写真のExifから自動入力（無ければファイルの更新日）。和暦・西暦の切り替えあり
- 黒板の移動: ドラッグ、矢印キー、四隅ボタン。大きさ: 右下の角のドラッグ、`+` / `-` キー、スライダー
- 黒板の色: 緑 / 黒 / 白
- 書き出しは長辺4096pxまでのJPEG
- 工事名・施工者・色・大きさ・項目の並びはブラウザに記憶されます（localStorage）
- 「すべての写真をサーバーに保存」: 写真が2枚以上あるとき、全部を順番にサーバーへ送ります。失敗した写真があっても残りは続けて保存し、最後に結果を表示します。同じ名前の写真には `_2`、`_3` を付けて区別します
- サーバーに保存（Vercel にデプロイしたときだけ表示）: 黒板つきの写真（JPEG）と、黒板の入力内容（JSON）を Vercel Blob に保存します。写真は送信用に約4MB以内へ縮小されます

## Vercel にデプロイして「サーバーに保存」を使う

`api/save.js` が保存を受け付けます。次の設定が必要です。

1. Vercel でこのリポジトリをインポートしてデプロイする（Framework Preset は「Other」）
2. プロジェクトの **Storage** タブで **Blob** ストアを作成し、このプロジェクトに接続する（環境変数 `BLOB_STORE_ID` などが自動で入ります。認証はVercelのOIDCで行うため、トークンの手入力は不要です）
3. **Settings → Environment Variables** に `SAVE_KEY` を追加する（保存用パスワード。社内で共有する合言葉を決めてください）
4. 再デプロイする

設定が終わると、画面の右側に「サーバーに保存」が出ます。保存用パスワードを入力して押すと、保存できます。
保存先は Vercel の **Storage → Blob** で確認できます。`kokuban/年-月/` の下に、写真（.jpg）と入力内容（.json）が入ります。

### 保存について

- 保存用パスワード（`SAVE_KEY`）が合っていないと保存できません。パスワードを知らない人は、アプリを開いても保存できません。
- 保存した写真のURLは、推測されにくい文字列がついていますが、URLを知っていれば誰でも見られます（公開設定の Blob）。URLの取り扱いに注意してください。
- `SAVE_KEY` は、コードや README に書かず、Vercel の環境変数にだけ入れてください。

## スマホアプリとして使う

### 1. ホーム画面に追加（PWA・すぐ使える）

Vercel の URL をスマホで開くだけで、アプリのように使えます。費用や審査はありません。

- **Android（Chrome）**: 画面の「ホーム画面に追加（アプリとして使う）」ボタン、またはメニューの「アプリをインストール」
- **iPhone（Safari）**: 共有ボタン →「ホーム画面に追加」
- 一度開けばオフラインでも起動します（サーバー保存だけは通信が必要です）。フォントは初回の読み込み後に保存されます
- スマホには「カメラで撮影」ボタンが出ます。撮ったらそのまま黒板を合成できます
- 保存は、画面に出る「共有・保存（写真アプリへ）」から写真アプリへ入れます

### 2. ネイティブアプリ（`native/`）

Capacitor で iOS / Android のアプリに包みます。画面は同じ `index.html` を使い、アプリ版では「この写真を保存」で**写真アプリに直接保存**されます（`@capacitor-community/media`）。

**Android（社内配布用 APK）— Mac不要**

1. GitHub の **Actions → Android APK → Run workflow**
2. 「サーバー保存に使うVercelのURL」に `https://（あなたのドメイン）.vercel.app` を入れる（サーバー保存を使わないなら空）
3. 終わったら実行結果の **Artifacts → kokuban-android-debug** から `app-debug.apk` をダウンロードし、スマホに入れてインストール（「提供元不明のアプリ」を許可）。Google Play には載せません

**iOS — Mac と Xcode が必要**

```bash
cd native
npm install --legacy-peer-deps
APP_URL=https://（あなたのドメイン）.vercel.app npm run build:web
npx cap add ios
npx cap sync ios
```

1. `python3 tools/ios_setup.py` を実行して、`Info.plist` に写真・カメラの使用目的と `kokuban://` のURLスキームを追加（`native` フォルダで）
2. `npx cap open ios` で Xcode を開き、Signing に Apple ID のチームを設定して、実機に入れる
3. 社内の他の端末へ配るには Apple Developer Program（年額 12,800円）に登録し、TestFlight か Apple Business Manager のカスタムApp配布を使います。無料の Apple ID だと、自分の端末に7日間だけ入れられます

> アプリ版の動作確認はこの環境（Linux）ではできていません。Android と iOS の実機で、撮影・合成・写真アプリへの保存・サーバー保存を確認してください。うまく保存できない場合は、画面に「共有・保存」ボタンが出ます。

## お知らせ画面（アップデート情報）

画面右上の「お知らせ」ボタンで、更新内容の一覧を見られます。新しいお知らせがあると、ベルに赤い点が付き、開くと「NEW」が付きます（既読は端末ごとに記憶）。

**更新したときの作業（2か所）**
1. `index.html` の `NEWS` の先頭に、お知らせを1件足す（`id` は前より大きい番号、`APP_VERSION` も更新）
2. `sw.js` の `VER` の番号を上げる（`kokuban-v2` → `kokuban-v3`）。アプリを開いている人には「アプリが更新されました。［再読み込み］」が出ます

## 現場アプリとの連携（案件情報を自動入力）

現場アプリの案件から黒板アプリを開くときに、案件の情報をリンクに付けると、必要な項目を読み取って入力欄に自動で入れます（黒板にも反映）。入れた項目は黒板に表示される設定になり、あとから自由に直せます。

**案件の写真の読み込み・案件への保存。** 現場管理アプリの案件の「連携アプリ → 黒板」から開くと、リンクに署名付きチケット（gk、12時間有効）が付き、その案件の写真を選んで読み込めます。黒板を付けた写真は「案件に保存」で案件の「写真・ファイル」に追加されます（現場管理アプリ側の /api/config の kokuban-* で処理。Vercelの環境変数 SSO_SECRET が必要。黒板アプリのURLを変えた場合は KOKUBAN_URL も）。

**入れる前に割り当てを確認します。** 案件情報が届くと「案件情報を黒板に入れる」画面が開き、黒板の欄（工事名・施工者・工種・測点・場所・部屋番号・備考）ごとに、届いた項目の中から入れるものを選べます（最初は項目名から見当をつけた候補が選ばれています）。「次から確認せずに入れる」にチェックすると、同じ項目の組み合わせで届いたときは自動で入ります。上の帯の「割り当てを直す」でいつでも選び直せます。

**1. リンクに付ける（いちばん簡単）**

```
https://（あなたのドメイン）.vercel.app/?工事名=南町マンション大規模修繕&施工者=株式会社三桜&工種=クリーニング工&場所=共用廊下&部屋番号=301&備考=足場解体後
```

値は URL エンコードしてください（`encodeURIComponent`）。`#` の後ろ（`#工事名=…`）でも同じです。

**2. 案件のデータ（JSON）をまとめて渡す**

項目名が現場アプリ側の名前のままでも、入れ子になっていても読み取ります。

```js
const project = { id: 55, project: { name: '南町マンション大規模修繕', contractor: { company: '株式会社三桜' }, location: '共用廊下' }, memo: '足場解体後' };
window.open('https://（あなたのドメイン）.vercel.app/?project=' + encodeURIComponent(JSON.stringify(project)));
```

`project=`（または `data=` / `info=` / `案件=`）に、JSON を URL エンコードしたもの、または base64（URL安全）にしたものを入れられます。

**3. postMessage で渡す（window.open で開く／iframeで埋め込む場合）**

```js
const w = window.open('https://（あなたのドメイン）.vercel.app/');
window.addEventListener('message', (e) => {
  if (e.source === w && e.data && e.data.type === 'kokuban:ready') {   // 黒板アプリの準備ができたら
    w.postMessage({ type: 'kokuban:project', source: '現場管理アプリ', project: { 工事名: '…', 施工者: '…' } }, 'https://（あなたのドメイン）.vercel.app');
  }
});
```

黒板アプリは、自分を開いた画面（または埋め込んだ画面）からのメッセージだけを受け取ります。

**読み取る項目名**（大文字小文字・空白・`_`・`-` は区別しません。左から優先）

| 黒板の項目 | 読み取る名前 |
|---|---|
| 工事名 | 工事名 / 工事名称 / 案件名 / 現場名 / kouji / project / projectName / siteName / title / name |
| 施工者 | 施工者 / 施工会社 / 請負者 / 会社名 / sekou / contractor / company / builder |
| 工種 | 工種 / kojishu / workType / trade |
| 測点・箇所 | 測点 / 箇所 / sokuten / station |
| 場所 | 場所 / 工事場所 / basho / place / location |
| 部屋番号 | 部屋番号 / 号室 / heya / room / roomNo |
| 備考 | 備考 / メモ / bikou / note / memo / remarks / comment |

- 撮影日は、写真のExifから自動で入ります（案件情報では入れません）
- 1項目あたり200文字まで。文字として扱うので、HTMLなどは実行されません
- 読み込んだあと、リンクの情報部分（`?…`）は消します。再読み込みしても二重に入りません
- 案件情報を使わずに開いたときは、前回の入力内容がそのまま残ります

**4. アプリ版（Android / iPhone のアプリ）を開く**

ネイティブ版の黒板アプリは、独自のリンク `kokuban://` で呼び出せます。つなぐ項目は、上の1〜2と同じです。

```
kokuban://open?工事名=南町マンション大規模修繕&施工者=株式会社三桜&場所=共用廊下
kokuban://open?project=（JSONをURLエンコードしたもの）
```

- 黒板アプリが閉じているときは、起動と同時に入力されます。すでに開いているときも受け取ります
- 現場アプリが Web（ブラウザ／ホーム画面のアプリ）なら、`location.href = 'kokuban://open?…'` で開けます。現場アプリが Capacitor 製なら `@capacitor/app-launcher` の `AppLauncher.openUrl({ url })` を使います
- 黒板アプリが入っていない端末では、リンクを開いても何も起きません。その場合に備えて、現場アプリ側で Web 版のリンク（上の1〜2）に切り替えるなどの用意をしてください
- 設定は、Android は Actions のビルドで自動的に入ります（`native/tools/android_scheme.py`）。iPhone は、Mac で `npx cap add ios` のあとに `python3 tools/ios_setup.py` を実行します（`kokuban` のURLスキームと、写真・カメラの使用目的を `Info.plist` に追加します）
- 現場アプリから開けるのは、`kokuban://` を知っているアプリだけで、他のアプリのリンクには反応しません（`kokuban:` で始まるリンクだけを読みます）
- Web のURL（`https://…`）で直接アプリ版を開く方式（Universal Links / App Links）は、ドメインの確認ファイルが必要なので、まだ対応していません

## 注意

- 公共工事の提出写真では、撮影後の加工を認めない基準があります。提出先の要領を確認してください。
- 書き出した画像には、元の写真のExif情報（撮影日時・位置情報）は引き継がれません。
- HEIC形式は多くのブラウザで読み込めません。JPEGに変換してください。

## 開発メモ

- 画面（`index.html`）は外部ライブラリなし。サーバー側（`api/save.js`）だけ `@vercel/blob` を使います。フォントは Google Fonts（Dela Gothic One / M PLUS Rounded 1c / Zen Kaku Gothic New）を読み込みます。
- 黒板は Canvas に描画しています。書き出し時は元の解像度（上限4096px）で描き直します。
